# 大学生创业实训平台 · 演示系统业务说明

> 本文档给产品、教务、开发、演示用的人看：说清楚「这个平台在讲什么业务」「演示里能点出什么」「和正式 PRD 差在哪」。  
> 依据：PRD V1.0 + 当前仓库前端实现（React 路由与页面）。

---

## 1. 这是什么东西

面向高校创新创业实训课：学生组队做项目，按阶段从创意走到商业计划书；教师盯进度、发任务、审材料、打分。

**当前仓库是「演示前端」**：界面和流程都搭好了，数据大多是本地 mock，登录是假流程（选角色后跳转），没有接真实后端。适合用来讲业务、走一遍操作路径，不能当生产系统用。

---

## 2. 谁在用（角色）

| 角色 | PRD 里 | 演示系统里 |
|------|--------|------------|
| 学生 | 有 | 首页选「学生」登录后进学生中心、知识系统、各实训页 |
| 教师 | 有 | 教师看板 + 课程设置、班级项目总览等 |
| 管理员 | PRD V1.0 写「暂不包含独立管理端」 | **代码里已有**管理后台（用户、班级、课程资源、操作日志），算演示扩展，方便讲「学校统一运维」 |

---

## 3. 一条主业务线（人话版）

学生先进课、组队，再按顺序做：想点子 → 做调研和用户画像 → 画产品/原型 → 搭商业模式 → 用 AI 辅助分工和仿真 → 写计划书和 PPT → 最后看成绩和老师反馈。  
老师这边：看全班各组卡在哪、发任务、审组队/选题/计划书、设截止和评分规则、给评价。

演示里**顺序可以乱点**，真实开课会由教师配置「解锁」和截止时间。

## 4. 八大模块分别干什么（对齐 PRD + 当前页面）

下面「演示里在哪」指主要入口；部分模块在学生中心里用 Tab 嵌了一套，和独立路由是同一套业务不同入口。

### 模块 0：组队（Team Formation）

- **业务**：几个人一队、谁当队长、分工大概怎样；老师可审、可调。学生完成测评与 AI 分析后，可选择 **进入组队池**（参与教师 AI 智能组队，通常 3～6 人）或 **成立单人公司**（即时生成 1 人团队，不参与智能组队，本人自动为队长）。
- **演示里在哪**：`/student-center?tab=module-team` 或 `/team-formation`；教师看板「组队审核」中单人公司团队带标签，互补得分显示为不适用。
- **后续实训**：单人公司仍按 `team_id` 走创意至计划书全流程，队长权限由唯一成员承担；组内协作、作战室多视角、互补分等能力在单人场景下教学意义减弱，但不阻断提交。
- **和 PRD 的差距（心里有数）**：PRD 里的规则校验、邀请次数、Excel 导出、热力图等，演示多为静态或局部交互，未接持久化。

### 模块 1：创新思维与创新方法（Ideation）

- **业务**：学点方法（头脑风暴、SCAMPER 等），团队产出多个创意再筛到 1～2 个，交报告给老师看。
- **演示里在哪**：学生中心「创新思维」Tab；独立页 `/ideation`。
- **差距**：协作讨论、投票、版本历史、抄袭检测等，PRD 写得很细，演示以展示为主。

### 模块 2：市场调研与用户画像（Market Research）

- **业务**：定调研计划、问卷、回收数据、画图、写结论，最后出用户画像和调研报告。
- **演示里在哪**：`/market-research`；学生中心「市场调研」Tab。
- **差距**：内置问卷真发放、录音转文字、教师看回收质量等，演示多为 mock 数据与表单展示。

### 模块 3：产品设计与原型（Product Design）

- **业务**：功能清单、用户旅程、线框/原型、说明文档，给老师审。
- **演示里在哪**：`/product-design`；学生中心「产品设计」Tab。
- **差距**：PRD 要求的「计划须先审再画」、完整协作与批注版本，演示未全流程强制。

### 模块 4：商业模式设计（Business Model）

- **业务**：商业画布、SWOT、营销与成本测算、六顶思考帽研讨等，合成一版商业模式方案。
- **演示里在哪**：`/business-model`、`/bmc-detail`；学生中心「商业模式」Tab。
- **差距**：成本计算器、一键 PDF、线上会议室式六帽记录等，演示有界面能力不等同于全功能落地。

### 模块 5：项目仿真与 AI 角色推荐（Role Simulation）

- **业务**：根据项目和成员特点，建议谁适合 CEO/CMO 等角色，队里再确认分工。
- **演示里在哪**：`/role-simulation`；学生中心「AI 仿真」Tab。
- **差距**：PRD 提到基于历史数据训练的模型；当前多为前端逻辑或占位，非真实模型训练闭环。

### 模块 6：商业计划书与 PPT（Business Plan）

- **业务**：把前几步成果收成计划书 + 路演材料，多版本、可再审。
- **演示里在哪**：`/business-plan`；学生中心「商业计划」Tab；教师看板「商业计划书审核」。
- **差距**：自动从各模块抽取填章节、真协同编辑 Word/PPT、模板引擎等，演示未接文档服务。

### 模块 7：教学评价（Teaching Evaluation）

- **业务**：老师按量规给过程分、成果分、协作分等，学生看反馈和报告。
- **演示里在哪**：`/evaluation`；教师看板「教学评价」Tab。
- **差距**：导出成绩单、与真实成绩系统打通等，演示未实现。

| 路由 | 用途（一句话） |

## 6. 教师看板、管理后台在演示里怎么理解

**教师看板**（`/teacher-dashboard`）：按侧栏分组——监控全班、评价/学情分析、班级与学生、任务与审核（任务发布、组队/选题/计划书审核）、总览与设置。和 PRD「教师盯过程、审成果、评价」一致。

**管理后台**（`/admin-dashboard`）：数据概览、用户、班级、课程资源、操作日志。PRD 说 V1.0 可不单独做管理员，这里当作**学校或平台运维演示**：真实立项时再定是否保留、权限怎么收。

---

## 7. 登录与数据（演示边界）

- 首页点登录：选学生/教师/管理员，**不验真账号**，只决定跳哪个工作台。
- 列表、进度、通知、审核队列等：**大量为 mock**，刷新或换浏览器不保证保留。
- 没有真实文件存储、没有真实 AI 计费、没有班级数据隔离的后端 enforcement——这些在接后端后要单独设计和验收。

---

## 8. 非功能需求在演示里的「对齐方式」（压缩版）

| PRD 类别 | 演示阶段怎么理解 |
|----------|------------------|
| 可用性 | 以当前 UI 为准，关键路径能点通即可 |
| 性能 | 未压测；PRD 写的 500+ 小组、原型 2 秒等，需等有后端和真实数据后再测 |
| 兼容性 | 前端为现代浏览器开发，建议 Chrome 演示 |
| 安全与隔离 | 演示无真实隔离；生产要做课程/班级级权限与审计 |
| 扩展性 | PRD 提 API、教务对接等，属后续迭代 |

## 9. 常用术语（很短）

- **商业画布（BMC）**：九块格子把「卖给谁、卖什么、怎么赚钱」说清楚。  
- **用户画像（Persona）**：虚构一个典型用户，把痛点、习惯写具体，方便产品设计对齐。  
- **Rubric（量规）**：评分表，每项几分、什么叫好什么叫差，写清楚减少扯皮。

## 10. 文档怎么用

- **给领导/老师演示**：从首页 → 选学生 → 学生中心按模块点一圈；再切教师看板看监控和审核。  
- **给开发对齐**：八模块 + 上表「多出来的页」= 现有路由范围；mock 字段可参考各页 `mockData` 与类型定义，不等于最终表结构。  
- **和 PRD 有出入时**：以 PRD 为业务真理源，以本文「当前实现」为演示事实源，差距列在第六节和第七节。
